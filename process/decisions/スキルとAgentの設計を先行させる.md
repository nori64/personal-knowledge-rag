# スキルとAgent自体の設計を先行させる（工程0の追加）

- 日付： 2026-11-26
- 状態： 採用
- 関係する工程： 工程0（新規追加）

## 背景
スキルとAgentを置くと決めて作った雛形を作成した直後、本人が指摘した：
「こうやって進めるための要件定義とか設計も必要だと思う。スキルやらAgentやらの設計」

つまり、スキルとAgentを量産する前に、「どういうスキル／Agentなら標準化と言えるか」の
要件と設計が先に必要だった。順番の間違い。

## 決定
- RAG本体の要件定義の前に「工程0： スキルとAgentの設計」を置く
- 成果物は docs/00-1_スキルとAgentの設計.md（要件全10項目、スキルの型、
  Agentの型、共通スキル、連携プロトコル、評価方法、未決事項3件）
- 雛形との差分（Agent定義にエスカレーションと完了報告形式がない、
  共通スキル未作成、ドライラン未実施）を棚卸しとして設計書に明記する

## 理由
- 型を決めずに量産したものは標準化の証拠にならない
- この順番の間違い自体が、過程の記録として価値がある（決定「過程自体をポートフォリオとして残す」）

## 影響
- 標準化の土台 v1.0 は、本設計の確認→差分反映をもって確定とする
- 要件定義工程の開始条件に工程0の完了が加わった
