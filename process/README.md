# process — 過程の記録（ポートフォリオの一部）

このプロジェクトでは、成果物（設計書・コード・テスト結果）だけでなく、
**そこに至る過程そのものをポートフォリオとして残す**（2026-11-26 本人の決定「過程自体をポートフォリオとして残す」）。

読み手（採用担当・レビュアー）に伝わるのは、完成品の出来だけではなく、
「どう決めたか、どこで順番を間違えてどう直したか、ゲートで何を確認したか」だから。

## 記録するもの

| 種類 | 置き場所 | いつ書くか |
|---|---|---|
| 意思決定記録（ADR形式） | `decisions/内容が分かるファイル名.md` | 方針・題材・技術・進め方を決めた／変えたとき、その場で |
| 工程記録 | `phases/<工程>_記録.md` | 各工程の開始時と終了時（ゲート判定・承認・差し戻し・振り返り） |
| 振り返り | 工程記録の末尾＋必要なら独立ファイル | 結果が出たとき。手順の反省だけでなく「構想・評価基準が実態とどこでずれたか」を書く |

## 記録の規則

- 決めたその日に書く。後から綺麗に書き直さない（訂正は追記で残す）
- 失敗・順番の間違い・差し戻しも消さない。それが過程の証拠になる
- 数字と日付は正確に。推測は推測と明記する

## 記録しないもの（公開リポジトリのため）

- 個人の事情（転職の動機、家計、年収など）。過程の記録は技術と進め方に限る
- 勤務先の情報、社内データ、実データ文書の中身
- 秘密情報（認証情報、個人を特定する情報）

この線引き自体も、共通スキル「公開前チェック」で各ゲートで確認する。
