- 照合相手： 外部設計書 v0.2（承認済み）、要件定義書 v1.0

## 指摘と対応

| 指摘 | 分類 | 対応 |
|---|---|---|
| スコアの正規化の方法が未定義で、やり方によっては候補あり判定が壊れる： 結果の中だけで最大・最小に合わせると、最上位は常に関連度1.0になり、閾値に意味がなくなる | 今すぐ直す | 正規化は「両方の検索で1位だった場合の理論上の最大値」で割る方式に固定した。絶対値に意味が残り、閾値判定が成り立つ |
| キーワード索引の保持方法が未記載だった（ベクトル側だけ設計されていた） | 今すぐ直す | 保存せず、検索と評価の開始時にチャンク情報から組み立てる、と決めた。規模が小さいため十分で、索引の版管理も1か所で済む |
| 質問セットのファイル形式（形式と項目）が未定義だった | 今すぐ直す | JSONL形式で、質問文／期待する文書名／期待する見出し／答えがない質問かの4項目と定義した |
| 設定ファイルに書く項目が、外部設計の分と内部設計で増えた分（モデル名、分かち書き方式、パラメータ）とで散らばっていた | 今すぐ直す | 設定項目の一覧表を内部設計に追加した |
| 初版の製造範囲が曖昧だった（MCPサーバーを初版で作るのかがモジュール表から読めなかった） | 今すぐ直す | 初版の製造はコマンドラインまでとし、MCPサーバーは結合テスト（外部結合）の前に作る、と明記した |
| 検索の簡易表示（本人が直接使う表示）の組み立てが、どのモジュールの責務か未記載だった | 今すぐ直す | コマンドラインのモジュール（cli）の責務として明記した |
| 埋め込み失敗時の終了コードへの変換が書かれていなかった | 今すぐ直す | 例外処理の表に、取り込みの実行失敗として終了コード4に変換することを追加した |
| PDF変換の道具（ライブラリ）の候補がなかった | 工程を明記して後へ送る | 第一候補は pypdf とし、製造の最初に動作を確認して確定する。内部設計には候補として追記した |
| 分かち書きで使う品詞の範囲（名詞だけか、全てか）が未定 | 工程を明記して後へ送る | 製造で決める小さな判断として残し、総合結合の評価で比べる対象に含める |

## 数で示す確認
