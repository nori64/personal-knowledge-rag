# ドライラン評価の結果： 共通スキル「自己レビュー」

- 日付： 2026-11-26
- 目的： 事情を知らないAgentにスキルだけを渡して、同じ品質で再現できるかを測る（差別化ポイントの「検討中」だった2件の実測）
- 方法： 外部設計書のコピーに欠陥を7件埋め込み、実施者にはスキル・対象・要件定義書の3点だけを渡した（元の設計書や過程の記録は見ない条件）

## 結果： 埋め込んだ欠陥7件中6件を検出（検出率 約86%）

| 埋め込んだ欠陥 | 検出 |
|---|---|
| 対応表から要件の行を削除（対応づけ漏れ） | 検出。要件14件と対応表13行を数えて特定した |
| 索引の配置を「本人のPC」と書き換え（前提の食い違い） | 検出 |
| JSON例の項目名を書き換え（形式の不整合） | 検出 |
| 終了コードを3から2に書き換え（不整合） | 検出 |
| 例外の表から「版が合わない」の行を削除（例外の欠落） | **未検出** |
| 構成図の中だけ旧コマンド名に戻す（表記ゆれ） | 検出 |
| 実データの質問文も公開すると書き換え（公開範囲の違反） | 検出 |

## 未検出の分析

- 「行が消えている」欠落は、比較の基準になる件数が無いと検出できない。実施者は例外の表を「5状況ある」と数えたが、あるべき件数を要件側が列挙していないため、消えた1行に気づけなかった
- 対策： 例外や振る舞いの一覧は、要件か前工程で「あるべきカテゴリ」を数えられる形で持ち、レビューでは件数を突き合わせる。自己レビュースキルの観点に、この進め方を追記した

## 埋め込み以外の、本物の指摘（3件）

ドライランは、ついでに実物の問題も見つけた。

1. 出典の「位置」が検索結果の形式に無い（要件は文書名・見出し・位置の3点）： 本物。対応として、検索結果JSONに位置を追加し、外部設計書（正本のExcel）へ改訂を記録した。単体テストも追加した（19件合格）
2. 候補なし時の hits の区別の形が未決定： 本物。has_answer_candidate が false であることで区別する形で確定し、外部設計書へ記録した
3. 「平たく言うと」に判断事項（PDFの範囲）が入っていない： 本物。外部設計書の要約へ追記した

## スキル側の改善

- 自己レビューの入力に「差別化ポイントの一覧」を追加した（今回、入力に無くて差別化の観点が判定不能になったため）
- 欠落の検出には基準の件数が必要、という進め方を観点に追記した

## 限界（正直な区別）

- 今回の実測は、自己レビュースキル×設計文書の1組み合わせだけ。他のスキル（図の作成など）の再現性は未実測で、差別化ポイントではその範囲を明記する
