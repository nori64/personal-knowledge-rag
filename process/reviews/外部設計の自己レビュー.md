# 自己レビュー記録： 外部設計書

- 日付： 2026-11-26
- 対象： docs/02_外部設計書.md v0.1
- 実施： 外部設計エージェント（共通スキル「自己レビュー」の手順による）
- 照合相手： 要件定義書 v1.0、決定「公開するのは実データ以外すべて」、基本設計の叩き台

## 指摘と対応

| 指摘 | 分類 | 対応 |
|---|---|---|
| 設定ファイル（文書フォルダの列挙先）がインターフェースなのに、名前・形式・置き場所が未定義だった | 今すぐ直す | 設定ファイルの節を追加した（ファイル名、書く項目、公開用サンプルと実物用の分け方） |
| 取り込みの出力が「標準出力に表示」だけで、機械（ネロ）が読む形式かどうか曖昧だった | 今すぐ直す | 取り込み結果もJSONを正の形式に統一した |
| 検索結果のスコアの意味（範囲、大小の意味）が未定義で、呼び出し側が解釈できなかった | 今すぐ直す | 統合後の関連度を0〜1に正規化し、大きいほど関連が強い、と定義した。算出方法は内部設計へ |
| 「答えの候補があるか」の期待水準が未定義で、判定方法を内部設計へ送るだけになっていた | 今すぐ直す | 外部仕様として期待（関連チャンクがあり、閾値以上のとき候補あり。閾値は評価で調整し、誤判定を評価結果に含める）を明記した |
| PDFの扱いが要件と設計でずれる恐れ： 要件では取り込み必須だが、最初の文書セットも評価もMarkdownが対象で、PDFの品質をどこまで保証するか未定義だった | 今すぐ直す（範囲の明記） | 「取り込みには対応するが、初版の評価と受け入れ判定の対象はMarkdownとテキストとする」と外部設計に明記した。要件側の優先度を下げる話ではないが、本人の確認事項として報告する |
| 埋め込みに外部APIを使う場合の、文書テキストの送信範囲がプライバシーの境界に書かれていなかった | 今すぐ直す | 境界の節に「外部APIを選ぶ場合は送信範囲と理由を内部設計書に明記し、本人の確認を取る」を追加した（要件の「ローカル動作」の文言と整合） |
| 索引の形式が将来変わった場合の振る舞い（古い索引を開いたとき）が未定義だった | 今すぐ直す | 例外時の表に「版が合わない索引は終了コード3で、再取り込みを促す」を追加した |
| 本人が直接コマンドを使う場面で、検索の人向け表示が「任意」のままで保証がなかった | 今すぐ直す | 簡易表示（文書名・見出し・一節の抜粋）を初版に含めることにした |
| MCPの通信方式を標準入出力と「前提」で置いていた | 許容して記録 | ローカル実行のMCPでは標準的な前提であり、内部設計で確定する事項として既に送り先が明記されているため、このままにする |
| 質問セットの項目（質問文、期待する文書と見出し、答えなし区分）は定義済みで、要件の「評価の算出」と対応している | 指摘なし | ― |

## 対応後の状態

- 外部設計書を v0.2 に改訂した（上記の「今すぐ直す」をすべて反映）
- 残件： PDFの範囲の明記は設計側の判断で入れたため、ゲートで本人の確認を取る
