# RAG 結合テスト3（IT3）スキル

## 目的

- 全体結合として、実データと実設定のまま、取り込み・索引・CLI・MCP・評価コマンドが一続きで期待どおり動くことを、テスト項目ごとの合格／不合格で判定する
- 検索品質の測定（Recallなど）はテストではない。評価として分けて記録し、合否に使う場合はSTで合格ラインを先に決める。モデル選定や方式の調整もテストではなく、設計・製造へのフィードバックとして扱う

## 入力

- IT2完了済みコード、実設定、実データ索引、実データ質問セット（いずれも非公開）

## 成果物

- IT3仕様書・結果（docs/IT3仕様書・結果.md）：テスト項目、期待、結果、合否。質問文など実データの中身は載せない
- 検索品質の評価結果は評価報告書（docs/08_評価結果.md）に分けて残す

## 手順

- 1. テスト項目を先に決める：索引の整合、差分取り込み、CLI検索（方式の指定あり・なし、答えあり・なし）、MCP経由の検索（答えあり・なし）、モデル不一致、索引なし、評価コマンドの実行
- 2. 項目ごとに期待（終了コード、候補あり判定、期待出典の有無、件数）を先に書き、実施結果と突き合わせて合否を付ける
- 3. 不合格が出たら欠陥として記録し、修正後にその項目を再実施する。修正が他へ影響する範囲は回帰確認する
- 4. 評価の数値（Recallなど）は合否に混ぜない。評価コマンドのテストは「実行できて集計が出ること」までを期待とする
- 5. 公開成果物に実データの内容（質問文、文書本文、索引）が混入していないか確認する

## ゲート（完了条件）

- 必須のテスト項目がすべて合格していること。不合格のまま完了にしない
- 実施中に直した欠陥は、修正内容と再実施の結果が記録されていること

## 失敗しやすい点

- 評価の数字をテストの合否と混同する／方式やモデルを調整しながら「テスト中」と言い続ける（調整はテストの外でやる）／実データの内容が公開リポジトリへ混入する

## 次工程への引き継ぎ

- 成果物の場所と、未決事項・差し戻し事項を明記して次工程Agentへ渡すこと。口頭だけの引き継ぎはしない

## 工程記録

- 工程の開始と終了時に、process/templates/phase-record-template.md の形式で工程記録を書き、process/phases/ に残すこと。ゲートは工程記録が書かれていることも条件とする

## 自己レビュー

- ゲート前に共通スキル「自己レビュー」（skills/common-self-review）で成果物を確認し、レビュー記録を process/reviews/ に残すこと。自己レビューが済むまでゲート判定に進まない
