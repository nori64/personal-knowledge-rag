# RAG 評価質問セットの作成 スキル（共通）

## 目的

- 検索の良し悪しを、感覚でなく数字で比べられる材料を作る

## いつ使うか

- 要件定義で評価の土台を作るとき、総合結合で実データ用を作るとき

## 入力

- 対象の文書セット（またはサンプル文書）

## 手順

- 1. 答えがある質問を、文書と見出しを分散させて作る（1つの文書に寄せない）。質問ごとに、期待する文書名と見出しを決めて書く
- 2. 答えがない質問を必ず混ぜる（目安は全体の2割）。対象の文書に無さそうな話題から作り、「無理に答えを作らないか」を測れるようにする
- 3. 質問文は、実際の聞き方に寄せる（文書の見出しをそのまま写した質問にしない）
- 4. 形式は1行1質問のJSONLとし、項目は質問文／期待する文書名／期待する見出し／答えがない質問かの4つに固定する
- 5. 件数を数えて記録する（総数、答えがある／ないの内訳）

## ゲート（完了条件）

- 評価の実行で形式エラーなく読み込めること。答えがない質問が含まれていること

## 失敗しやすい点

- 答えがある質問だけ作り、誤判定（ないのに「ある」と返す）を測れない
- 実データの質問文を公開物に混ぜる。公開するのは架空サンプルの質問だけ

## 次工程への引き継ぎ

- 質問セットは評価の入力として版を固定する。途中で質問を変えたら、数字の比較ができなくなるため、変えた場合はその旨を評価結果に書く
