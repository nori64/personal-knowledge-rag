# 00_工程定義 — 個人用ナレッジRAG

本プロジェクトは、要件定義からSTまでの全工程を踏んで進める。
各工程には標準手順（スキル）と担当Agentを定義し、工程を飛ばさない。

## 進め方の原則

1. **工程を飛ばさない**：前工程のゲートを満たしてから次へ進む。急ぐ場合も、省略したことを記録する
2. **生成と検証を分ける**：成果物を作ったAgentと、次工程で検証するAgentは別の目で見る
3. **数字は先に盛らない**：目標値はベースライン実測の後に設定する。評価は先に決めたセットで測る
4. **最終判断は人が握る**：各ゲートの承認とSTの受け入れ判定は本人が行う。Agentは材料を揃えるところまで
5. **公開と私用を分ける**：公開リポジトリにはコードと架空サンプルだけ。実データとその評価結果はPC上だけに置く
6. **ゲート前に自己レビューする**：各工程の成果物は、共通スキル「自己レビュー」で確認し、レビュー記録（process/reviews/）を残してからゲートに進む
7. **手順は細かくスキル化する**：作業の中で再利用できる手順（図の作り方、文章の構成、変換の仕方など）が出てきたら、工程スキルとは別に共通スキルとして切り出す（2026-11-26 本人方針）
7. **設計差し戻しを恥じない**：後工程で見つけた設計の問題は、前工程の成果物を更新してから進める。その履歴も残す

## スキルとAgentの置き場所

- `skills/<工程>/SKILL.md` ＋ `skill.yaml`：その工程の標準手順。Agent Skills形式に寄せ、他の環境（Muse / Copilot等）へ持ち出せる形にする
- `agents/<工程>.agent.md`：その工程を担当するAgentの役割定義（使命、責務、禁止事項、入出力、使うスキル、承認点）
- `agents/00-orchestrator.agent.md`：全工程の進行管理Agent。工程の状態管理とゲート確認を担い、実作業は各工程Agentへ委任する
