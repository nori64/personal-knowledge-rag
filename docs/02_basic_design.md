# 02_基本設計書 — 個人用ナレッジRAG

- バージョン：v0.1（叩き台。正式版は `02_外部設計書.md` に統合済み）
- 対応：`01_requirements.md` v0.1

## 1. 設計判断

### 1.1 検索と生成を分ける（最重要）
- 検索（取り込み・埋め込み・ベクトル検索）は本人のPC上のローカル処理
- 生成（回答文の作成）は呼び出し側のエージェント（ネロ）が担う
- 理由：(1) 個人文書の全文を外部に送らない (2) エージェントを替えても検索基盤が残る
  (3) 検索だけを独立に評価できる（Recall@5 は生成モデルに依存しない）

### 1.2 埋め込みモデルは評価で決める
候補を実測で比べる。日本語の言い換え検索が効くかが勝負。
- 候補A：multilingual-e5-small / base（ローカル、過去に別用途でゲート未達の経験あり。そのまま採用しない）
- 候補B：bge-multilingual 系（ローカル）
- 候補C：外部APIの埋め込み（精度は高いが、文書テキストを外部送信するトレードオフを明記して判断）

### 1.3 ハイブリッド検索を前提にする
ベクトル検索だけでは、型番・固有名詞・数字（「26日」「40.04㎡」）に弱い。
キーワード検索（BM25）とベクトル検索を組み合わせ、結果を統合する構成を基本とする。
ベースライン（キーワードのみ）との比較を評価に必ず含める。

### 1.4 ベクトルDBはファイルベース
常駐サーバーは運用が重い。ファイルベースのDBをPC上に置き、
CLI／MCPのプロセスが開いて使う形にする。

## 2. 全体構成

```
取り込み（ingest）
  文書フォルダ ─► パーサ（md/txt/pdf）─► チャンカー（見出し単位＋長さ上限）
              ─► 埋め込み ─► ベクトルDB ＋ キーワード索引（出典メタデータ付き）

検索（search）
  質問 ─► 埋め込み ＋ キーワード検索 ─► 統合・（任意でリランク）
       ─► 上位チャンクを出典付きJSONで返却 ─► エージェントが回答生成

評価（eval）
  評価セット（質問／期待出典／答えなし区分）─► search を一括実行
  ─► Recall@5・出典正確率・答えなし検出率を算出し、結果表を出力
```

## 3. データ形式

- チャンク：`chunk_id, doc_name, heading, text, source_path(ローカル用、公開しない), updated_at`
- 検索結果：`query, hits[{chunk_id, doc_name, heading, score, text}], has_answer_candidate(bool)`
- 評価セット：`question, expected_doc, expected_heading, is_unanswerable`

## 4. インターフェース

- CLI：`rag ingest [folder]` / `rag search "質問" [--top-k 5] [--json]` / `rag eval`
  - ネロからは PC への SSH／対話セッション経由で呼ぶ（既存の自作CLIと同じ運用）
- MCP（第2段階）：`search_knowledge(query, top_k)` の1ツールをまず提供する

## 5. セキュリティ・プライバシー

- 実データのフォルダとDBは `.gitignore` で公開対象から外し、公開前に混入チェックを行う
- APIキーが必要な構成にする場合も、キーは環境変数／資格情報ストアのみ
- 検索結果をエージェントに渡す際も、質問に無関係な文書は渡らない設計（top-k のチャンクのみ）
