# 05_UT仕様書 — 単体テスト

> **平たく言うと**：部品ごとのテスト。文書の切り方、検索の合体の計算、評価の計算、設定の読み込み、差分取り込みが、決めたとおりに動くかを小さなデータで確かめる。意味検索のモデルは使わず、テスト用の代役で配線だけを見る。

- バージョン：v1.0（2026-11-26）
- 実施方法：Python標準の unittest。`tests/` 配下に置き、次で実行する

```bash
.venv/bin/python -m unittest discover -s tests
```

## テスト項目

| 対象 | 項目 |
|---|---|
| 文書の分割 | 見出しが出典に付くこと／長い節が上限以下に割れること／1段落が長い場合に重なりつきで割れること／空の節はチャンクにならないこと |
| 文書の読み取り | Markdownの見出しで節に分かれること／見出しなし文書は文書名が見出しになること／テキストは段落で分かれること |
| 検索の統合計算 | 順位の統合が手計算と一致すること／正規化で両方1位が関連度1.0になること／単独の検索でも正規化が成り立つこと |
| 設定 | ファイルが無い・必須項目が無いと、分かる理由で失敗すること／相対パスが設定ファイルの場所から解決されること |
| 取り込みと差分 | 初回は全件が対象になること／2回目は変更0件になること／変更したファイルだけ差分になること／消したファイルが索引から消えること |
| 文書名の付け方 | フォルダが違う同名ファイルが、別々の文書として区別できること |
| 評価 | 質問セットの形式が違うと行番号つきで失敗すること／小さなデータで Recall@5 と出典の正確率が手計算どおりになること |

## 結果（2026-11-26）

- 25件すべて合格
- 内訳：分割4件、読み取り3件、統合計算3件、設定3件、取り込みと差分2件、文書名2件、評価2件、検索結果の形式1件、候補あり判定2件、対象ファイルのパターン指定1件、CLIの既定方式1件、埋め込み文脈の切り替え1件（IT1〜IT3とドライラン評価、品質改善で追加）
